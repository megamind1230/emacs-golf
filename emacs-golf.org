** 2. Challenge ideas
*** A. Basic editing and navigation
**** 01 --- The Word Assassin

Starting text: =The quick brown fox jumps over the lazy dog.=

Delete =brown= without deleting either surrounding word.

**** 02 --- Sentence Surgery

Change =I really really like Emacs.= to =I really like Emacs.= Delete
only the second =really=.

**** 03 --- The Line Hopper

Move from the beginning of line 1 to the beginning of line 12 in a fixed
20-line buffer.

**** 04 --- Punctuation Surgery

Transform =Hello ,world != into =Hello, world!=.

**** 05 --- Duplicate Trouble

Given =apple banana cherry=, duplicate the entire line immediately below
it.

**** 06 --- End of the World

From the start of a 100-line buffer, jump to the final character of the
final line.

**** 07 --- Line Exterminator

Delete the current line, including its newline, without leaving an empty
line behind.

**** 08 --- Finders Keepers

Jump to the third occurrence of =Emacs= in a paragraph, starting at the
beginning.

** 3. How people should comment their answers
This is probably the most important part. You want comments to be easy
to compare, reproduce, and learn from --- not just screenshots of
someone typing =M-x= and claiming victory.

I'd use a standard comment template like this:

Writing

*Solution:* =C-a C-k C-y=

*Keystrokes:* 3 *Commands:* 3 *Method:* Vanilla Emacs *Setup required:*
None

*Explanation:* Go to the beginning of the line, kill it, then yank it
back.

*Tested on:* GNU Emacs 30.2, Linux

*Golfed by:* u/example

The numbers and explanation above are illustrative; each participant
should count their actual solution.

*** Recommended comment format
Ask everyone to include these fields:

- Solution: The exact sequence of keys or commands.

- Score: The number of keystrokes according to the challenge's rules.

- Method: Vanilla Emacs, Evil, Meow, macros, Elisp, external tools, etc.

- Setup: Any custom keybindings, functions, packages, or configuration
  required.

- Explanation: A short description of how the solution works.

- Proof: Optional recording, screenshot, or reproducible test.

For Elisp solutions, use a separate format:

Writing

*Solution:*

#+begin_example
(delete-duplicate-lines)
#+end_example

*Elisp length:* 23 characters *Invocations:* 1 *Requirements:* Command
available in the current Emacs setup.

*Explanation:* Describe what the expression does and any assumptions.

*Verified:* Yes / No

The code here is only a format example, not a guarantee that the
expression implements any particular challenge.

Important: Don't force all submissions into one scoring system. A
three-keystroke macro invocation and a 40-character Elisp function are
measuring different things.

** 4. Rules for the subreddit
I'd publish a short ruleset with every challenge.

** Emacs Golf rules
1. Everything is allowed. Vanilla Emacs, Evil, Meow, packages, custom
   functions, macros, registers, shell commands, and external programs
   are permitted unless a challenge explicitly defines a separate
   category.

2. The final result must be correct. The buffer or Emacs state must
   match the specified target exactly.

3. State the starting conditions. Every challenge must define the
   initial text, point position, active mode, and any relevant state.

4. Disclose prerequisites. If a solution requires a custom binding or
   installed package, include it.

5. Report honest scores. Count the solution according to the posted
   metric. Don't omit setup steps that are part of the measured run.

6. No restriction on cleverness. Built-ins, regexes, macros, code
   evaluation, and custom commands are all legitimate solutions.

7. Correctness beats brevity. A shorter solution that breaks the text or
   misses an occurrence loses to a correct one.

8. Improvement is encouraged. Reply to another person's solution with a
   shorter or more interesting alternative.

One nuance: I'd distinguish between setup and execution. Installing a
package or defining a function can be excluded from the execution score
if declared in advance. Otherwise, someone could hide an arbitrarily
complicated solution in their init file and claim a one-key victory.
That is still allowed under your rules --- it just belongs on the
custom-setup leaderboard.

** 5. A scoring system that rewards different kinds of golfers
Rather than maintaining one leaderboard, I'd have several.

| Leaderboard    | What counts                                                     |
|----------------+-----------------------------------------------------------------|
| Pure Golf      | Fewest key events under the challenge's stated convention       |
| Elisp Golf     | Shortest working Elisp source                                   |
| Macro Golf     | Fewest execution keystrokes using a declared macro              |
| Clever Golf    | Community votes for the most ingenious solution                 |
| Practical Golf | Best balance of brevity, readability, and real-world usefulness |
| Anything Goes  | Any correct solution, with its technique disclosed              |

You could also add a Vanilla Emacs category for people who want to learn
the built-in editor, but don't make it the default restriction.

I'd explicitly define how to count modifier keys. My preference is to
count each key event as one stroke, including chords such as =C-a= and
=M-f= as one stroke each, and to report any multi-key sequences
separately if necessary. That keeps scoring simple and avoids debates
about how long someone physically holds Ctrl.

** 6. A ready-to-post first Reddit challenge
Here's how I'd launch the idea on a subreddit such as r/emacs.

Emacs Golf #001 --- Delete the Word

** exmaple Emacs Golf #001 --- Delete the Word
Welcome to *Emacs Golf*, a challenge series inspired by Vim Golf.

The goal: complete the editing task using the fewest keystrokes
possible.

** The challenge
Starting buffer:

#+begin_example
The quick brown fox jumps over the lazy dog.
#+end_example

Your cursor is at the beginning of the line.

Target buffer:

#+begin_example
The quick fox jumps over the lazy dog.
#+end_example

Delete =brown= , including its trailing space, without changing anything
else.

** Rules
- Everything is allowed: vanilla Emacs, Evil, Meow, packages, macros,
  Elisp, custom keybindings, and external tools.

- Your solution must produce the exact target buffer.

- State any setup or custom configuration your solution requires.

- Count execution keystrokes, not the time it took you to configure
  Emacs.

- Use one key event per stroke; a chord such as =C-a= counts as one
  stroke.

- If your solution uses a macro or custom command, disclose it.

- Bonus points for an elegant solution that teaches people something
  new.

** How to submit
#+begin_example
Solution:
Score:
Method:
Setup:
Explanation:
#+end_example

You can post multiple solutions if you find different approaches.

*The goal isn't to prove that one editing style is superior. It's to
discover how many different ways Emacs can solve the same problem.*

What's your score?

May the shortest sequence win.
